# 代码审查与验收规范

适用于 RESTModel 主包体系、扩展包、工具、测试、配置与包交付。全量检查覆盖约定范围内全部生产模块；专项检查选择相关条目并追查上下游。以下层级是审查视角，不要求按层级拆包。

## 使用方法与证据

1. 确认现行合同、对象、公开入口、执行范围及源码基线。
2. 全量覆盖 L0—L7；专项按索引选择条目并记录不适用项依据。
3. 每条记录源码位置、调用链、方法、实际结果及证据；发现问题后复查原触发条件与相邻消费者。
4. 结论不超过证据范围。稳定编号用于引用，新增条目不重排旧编号。

本规范独立适用于本仓库，不继承其他项目的服务端、数据库、Agent 或 UI 专项要求。未来新增能力后按实际风险补条目，不因规范存在而要求实现缓存、重试或流式支持。

## L0：合同与范围

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| G01 | 按已确定合同判断行为，区别正式参考、设计提案与实施状态；保留资源化、链式与 RESTful 省配目标。 | 合同来源及真实使用例。 |
| G02 | 盘点公开入口、内部模块、扩展、依赖和环境；不只查测试加载模块。 | 清单及排除依据。 |
| G03 | 保留既有和并行修改，区分源码、锁、dist、tarball 与 registry，不 reset 或清理用户数据。 | 版本/文件基线与产物来源。 |
| G04 | 文档、离线测试、本地 HTTP、真实服务、发布与压测分别按任务范围执行；不自动扩大为外部写入。 | 执行对象、环境、数据与副作用边界。 |
| G05 | 用最小有效验证回答具体疑问；通过后不无理由反复构建或测试。 | 实际命令、目的及未验证项。 |

## L1：接口与配置

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| I01 | 标准资源声明能力后可推导接口，不要求逐项配置方法和路径；增加例外沿用同一模型。 | 标准、变体、特殊接口的连续例子。 |
| I02 | 缺省无能力，预设显式继承；列表、星号、false、方法覆盖和资源形态遵守操作合同，特殊动作不进入星号。 | 声明和归一化正反例。 |
| I03 | scheme 只适配协议，能力目录决定允许操作；服务规则一次配置、资源和操作覆盖例外。 | 配置优先级及跨资源复用用例。 |
| I04 | 缺失、0、空字符串、空数组、false、undefined、空 body、未知 total 含义清楚。 | 默认、空值、冲突与关闭用例。 |
| I05 | 短写/完整写法结果同形；公共 import、命名、输入方向、错误与结果统一。 | 消费示例及导出核对。 |
| I06 | 泛型推断、类型拒绝与运行时检查分别成立；未知值不凭断言变成模型。 | 正反类型用例和动态输入测试。 |
| I07 | 公开可选实现使用同一契约；没有 Axios 类型泄漏、特殊 helper 标记或开发期无限兼容别名。 | 自定义/现成 Transport 接线与依赖图。 |

## L2：职责、组织与书写

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| A01 | 声明、解析、请求构造、执行和结果适配职责可追踪；聚合入口复用同一实现。 | 实际调用链。 |
| A02 | 操作等有限能力目录实际驱动校验、默认值、星号与分发，无平行全集。 | 目录及消费者对照。 |
| A03 | scheme 不依赖 Axios；Mock 服从最终 HTTP；缓存不对接任意业务 Store；Pinia 不进入主包。 | 源码导入和扩展入口。 |
| A04 | 跨包仅依赖公共 exports，manifest 声明完整；伪三方没有内部特权。 | 导入图、manifest 与类型解析。 |
| A05 | 拆分有独立职责/消费者，不复制文件改名称，不为行数产生跳转链或空包。 | 重复实现和复用入口对照。 |
| A06 | 文件按领域、生产/测试/文档/产物归属，迁移同步所有引用。 | 目录和编译/测试入口。 |
| C01 | 排版遵循统一配置，无手写多语句堆叠；工具已配置才能声称格式检查通过。 | 格式配置、执行范围及 diff。 |
| C02 | 生产模块说明职责，公共函数参数/返回/异常、公开字段与关键常量有必要说明。 | 源码注释与行为对照。 |
| C03 | 注释解释非显然原因，不机械复述；测试/临时脚本不套生产逐函数注释要求。 | 注释抽查及文件分类。 |
| C04 | ESM、类型导入、命名和错误处理符合代码规范，any/断言不替代边界检查。 | 类型检查和关键边界审阅。 |

## L3：逻辑、类型与 HTTP 协议

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| B01 | 继承终止、能力展开与具体覆盖顺序确定，不随对象键顺序改变。 | 循环、重复、先后顺序与形态测试。 |
| B02 | URL、身份、query 与 body 按阶段编码；0、复合身份、斜杠、Unicode、重复 query 不丢语义。 | 最终 HTTP 请求及往返边界。 |
| B03 | GET/list、PUT/PATCH、集合/成员/单体分清；不支持操作在请求前拒绝。 | 操作位置与无副作用负例。 |
| B04 | scheme 继承、数组/函数替换、关闭与分页模式切换不保留错误字段，不盲目 deep merge。 | 最终配置及局部覆盖矩阵。 |
| B05 | Transport 统一处理 HTTP 非 2xx；无响应网络/取消/超时与业务错误不混淆；保留 cause。 | Axios/自定义实现同形用例。 |
| B06 | 信封、裸数组、分页、204/205、标量/null/undefined 与错误结果按合同处理。 | 请求到公共结果的完整样例。 |
| B07 | 返回对象键枚举、JSON、字段赋值、关系冲突与身份缺失符合合同，不靠原型代理伪装普通对象。 | Object.keys/展开/JSON/关联调用测试。 |

## L4：并发、生命周期与扩展一致性

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| D01 | 共享定义、不可变链与单次请求状态隔离，两个分支并发不串 query/identity/headers。 | 交错执行与快照用例。 |
| D02 | 取消等待、终止实际请求与撤销服务端副作用分别说明；timer/listener 完整释放。 | 慢请求、取消、超时与后续调用。 |
| D03 | 如有重试/合并，幂等、预算、取消及多个消费者关系明确；不默认重试写操作。 | 请求次数、响应丢失和取消用例；无此能力则不适用。 |
| D04 | 如有缓存，遵守本库结构，键包含必要身份/参数范围，TTL/失效/容量明确。 | 跨客户端身份、参数、写后失效及过期用例；无缓存则不适用。 |
| D05 | Mock 使用与真实执行相同的推导、鉴权准备和编码链；匹配失败/透传规则明确。 | 最终请求对照；不以 Mock 证明真实网络。 |
| D06 | 状态管理扩展处理迟到结果、取消与销毁，不把框架生命周期塞进核心。 | 多订阅者、切换与清理用例；按扩展适用性选。 |

## L5：安全与信任边界

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| S01 | 动态键、未知字段、深度和规模在真实入口验证，防止原型污染、无限递归及恶意属性执行。 | 非法键、循环、异常 getter/实例边界。 |
| S02 | URL/path/origin 约束符合合同；凭据不随重定向或跨服务配置意外泄漏。宿主 SSRF 策略与库保证区分。 | 路径逃逸、绝对 URL 与重定向策略对照。 |
| S03 | 日志、错误和诊断不泄漏 Authorization、Cookie、密码或敏感 body；不默认打印真实请求。 | 合成敏感值与输出检查。 |
| S04 | Mock/缓存不绕过认证，不把命中缓存当业务授权；资源白名单不是服务端权限控制。 | 拒绝路径与扩展边界。 |
| S05 | 核对实际依赖闭包、锁、安装脚本和 peer 范围，区分公告命中与可达风险。 | 解析版本、用途和适用回归。 |

## L6：性能与稳健性

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| R01 | 配置解析、链分支、代理和结果包装不重复复制全树；规模增长有合理成本。 | 工作量计数及必要基准，结果等价。 |
| R02 | timer、signal listener、连接、流与缓存生命周期完整，不保留无界全局实例。 | 失败/取消/销毁后恢复与资源计数。 |
| R03 | 可选诊断或观测失败不重复请求、覆盖业务错误或改变授权。 | 故障注入和真实调用次数。 |
| R04 | 性能结论标明环境、数据、样本与对照；类型测试/Mock/并发正确性不等于浏览器表现或网络容量。 | 原始指标、范围和基线。 |
| R05 | core 依赖图不意外携带 Axios/Mock.js/Pinia、Node 专用模块或无关运行库。 | 实际产物、导入闭包与必要体积对照。 |

压测只在任务明确涵盖且环境专用、稳定、隔离时执行；不因整理规范、普通代码检查或本地回环服务自动启动。性能优化应由可靠证据驱动，不能以单次耗时或追加无目标测量得出容量结论。

## L7：验证与包交付

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| V01 | 测试验证行为与边界，不 mock 掉被测规则、不改期望迎合缺陷。类型、离线、HTTP 集成与外部服务证据分开。 | 用例到合同/分支的映射。 |
| V02 | 覆盖率若被要求，分母含全部范围内生产模块，未加载逻辑不隐去。 | 工具、范围、未覆盖与合理排除。 |
| V03 | 按改动选择最小有效检查，修复后验证共同路径和消费者；未经验证不标通过。 | 实际命令与复查结果。 |
| V04 | exports、types、ESM、peer、构建产物与 README 在实际包体可消费；本地源码可运行不等于包可发布。 | tarball 或明确的安装消费验证。 |
| V05 | 接口、默认值、文档、示例和脚本同步，正式参考与过程资料分离。 | 责任文档与来源链接。 |
| V06 | 发布只在明确授权下执行，执行后核对 registry 版本、标签、完整性和文档。 | 真实回执及公共读取证据。 |

不得通过删守卫、放宽校验、缩小覆盖范围、跳过未加载模块或只运行缺陷探针制造通过。没有全量证据就不写“全部安全”“所有分支通过”。

## 结论与记录

状态为通过、不通过、未验证、不适用。不适用需有依据；证据不足不能标不适用。发现注明已复现、源码确认、公告命中或条件性推导，严重程度按触发条件、影响和恢复成本判断。

存在未关闭的不通过，或缺少本次任务要求的验证时，整体不能标验收通过。长期记录放 docs/maintenance，临时原始输出放临时目录；不写入本规范正文。
