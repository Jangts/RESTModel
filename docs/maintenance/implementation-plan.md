# 实施计划与验收门槛

本文件记录后续实施顺序，不是可用 API 参考，也不代表架构草案中的接口已经定稿。现有合同以[资源操作声明](../operations.md)和[项目边界](../project-scope.md)为准；拟议接口见[架构草案](../design/core-architecture.md)。

## 当前基线

P0 声明收尾与 P1—P6 的首版运行闭环已实现，当前 API 以正式参考为准。P7 已完成本地 tarball 消费验证，不包含公开发布；Chrome 已完成最小实测，其他浏览器、动态类型边界与分发许可仍单独跟踪。具体证据见[首版闭环验收记录](runtime-verification.md)。

## 实施原则

每个阶段完成一个可观察的调用闭环，同步公开入口、类型正反例、运行时边界、责任文档和审查证据，再进入依赖它的阶段。内部模块按职责建立，不预先创建独立 http/shared 包。

操作目录继续作为标准方法、目标位置和能力的唯一来源；后续请求构造、结果分发应扩展该目录，不复制另一份标准操作全集。scheme 只能调整已开放能力的 HTTP 适配。

新增语法先收敛最小合同，再写实现。设计草案中未定接口只在设计文档讨论，不提前进入公共 README。缓存、重试、刷新 token 队列与发布不属于以下默认交付范围。

## 阶段与依赖

| --- | --- | --- |

| P1 HTTP 执行契约 | 中立 Transport、请求/响应、错误与公共执行流程 | 自定义执行器完成成功/失败/取消闭环 |

| P3 服务适配 | scheme 继承、信封、查询及分页 | 两类服务规则复用与模式切换矩阵通过 |
| P4 资源关系与结果 | children/members、ResourceList、实体及关联访问 | 嵌套路径、序列化、字段冲突与身份缺失测试通过 |

| P6 扩展验证 | Axios → HTTP Mock → Pinia | 公共包契约消费及各扩展边界测试通过 |

### P0：声明边界收尾

1. 区分 ResourceConfig 与 ResourcePreset 的已知字段，确定并实现未知字段拒绝策略，避免动态输入中的拼写错误被静默忽略；现有声明文档尚未承诺拒绝根级未知字段，变更需同步说明。
2. 逐字段明确缺失、显式 undefined 与 null：operations/extends 缺省或 undefined 的继承语义，kind 是否接受 null。类型限制和运行时规则分别验证，不让空值策略由 `??` 偶然决定。
3. 补充 Object.prototype 上的继承字段、非枚举字段、异常输入及方法覆盖的共同路径回归；确认快照和归一化不会再次从原型链取得星号或方法。
4. 改善错误定位，提供字段路径和阶段；错误描述不调用未知对象的自定义字符串转换，也不携带敏感配置内容。

验收对应 I04/I06、C04、S01、V01/V03/V05。保留全部现有能力、冻结和继承回归，不为边界加固改变星号或 false 优先级。

### P1：HTTP 执行契约

先在 core 内建立实际职责模块。定义不含 Axios 类型的 HttpRequest、HttpResponse、Transport，明确 body 编码归属、响应解码归属和 headers 的大小写处理。录制执行器只作为测试夹具，不成为第二条执行流程。

公共流程统一处理 HTTP 非 2xx；Transport 保留正常 HTTP 响应，只把无响应的网络、超时、取消作为执行失败。错误保留 cause，公开诊断默认脱敏。原始 request/response 的程序化访问与安全展示分别定义。

明确谁拥有 timeout、AbortSignal 监听和清理；不把停止等待当成请求已终止。prepareRequest 只执行一次，可选观察器失败不得重发或覆盖业务结果。用慢执行器、预先取消、执行中取消和失败注入验证调用次数与资源释放。

验收对应 I07、B05/B06、D02、S02/S03、R02/R03。此阶段不声称真实网络或 Axios 验证完成。

### P2：最小资源调用闭环

设计例子收敛到一个已显式声明 operations 的 users 集合和一个 settings 单体。实现 Client 装配、不可变引用、绑定身份、query/with 及目录驱动的标准终端操作。返回值先通过共同响应适配入口返回普通数据，完整实体与列表形态在 P4 完成前不得宣称客户端首版合同稳定。

路径按片段编码；验证身份 0、复合身份、斜杠、Unicode、缺失身份和服务 baseURL 路径。拒绝路径逃逸与非授权绝对 URL。不支持操作必须在鉴权准备和 Transport 等副作用前失败。

验证两个链分支交错执行不串 identity/query/headers/signal；查询重复键、undefined 删除及调用时快照有确定语义。同步维护公开入口的真实消费类型用例。

验收对应 I01/I02/I05/I06、A01/A02、B02/B03、D01、S01/S02。

### P3：scheme 与分页

按已知 schema 实现默认 → 客户端 → 祖先资源 → 当前资源 → 当前操作的优先级；数组和函数替换、undefined 继承、允许字段的 false 关闭分别定义。

先验证裸 body/裸数组与 envelope + items/total，再扩展 page/size、offset/limit 和 cursor/limit。分页模式切换整体替换，不能留下上一模式字段。page 与 cursor 在类型和运行时均互斥，未知 total 保留 undefined，204/205 不补请求。

验收对应 I03/I04、B04/B06、V01。至少两个不同服务共享资源调用写法，证明配置随差异增长，而非逐接口重配。

### P4：关系、列表与实体

先在设计草案收敛 children/members、ResourceList、dataOf/resourceOf 的最小签名及保留名。声明层与运行时同步支持嵌套集合/单体，关系必须显式声明。

列表不伪装 Array；对象数据与关联能力遵守数据字段优先。验证 Object.keys、展开、JSON、赋值、冻结输入和字段冲突。scalar/null/undefined 原样处理，缺失身份不能产生 undefined 路径；本地修改不自动发送请求。

验收对应 I06、B07、D01、R01。必要规模检查只验证工作量和等价性，不据此宣称浏览器性能或网络容量。

### P5：特殊接口与控制面

显式 action 的 method/path/input 布局沿用同一 HTTP 流程，标准星号不包含 action。核对集合、成员、单体动作位置和返回适配策略。

明确 `$`、then、危险键及资源/控制方法冲突规则；raw HTTP 返回原始响应，不隐式套资源信封。避免为各返回模式复制终端方法。

验收对应 I01/I05、A02、B02/B03、S01/S02、R03。

### P6：扩展接入

- Axios：只导入 core 公共入口，显式 peer；本地 HTTP 服务验证非 2xx 转换、body、取消与超时，不能只依赖 mock Axios 对象。
- Mock：包装相同 Transport 流程，匹配最终 method/URL/headers/body；验证未命中报错/透传策略、鉴权准备与真实请求一致性。
- Pinia：最后接入；先收敛最小公开用途，再验证切换后的迟到响应、多订阅者取消及销毁清理。

验收对应 A03/A04、B05、D02/D05/D06、S04、R02/R05。某扩展未实现不阻塞其他已完成包的独立验证，不用占位 API 充数。

### P7：交付准备

对实际 tarball 在临时目录安装，分别验证 ESM import、声明类型、公开 exports、依赖闭包、README 链接与许可。仓库源码测试不能替代包消费验证。实际支持环境按产物与依赖证明，浏览器验证另列证据。

只有出现独立 HTTP 消费者且具备可独立运行的 HTTP 执行层，才重新评估拆包；不以模块数量作为拆包理由。依赖公告另行联网核对，记录命中版本与可达范围。发布需明确授权，打包验收不自动发布。

验收对应 S05、R05、V04/V05/V06。

## 下一实施单元

P0—P6 已完成当前首版运行闭环，P7 以实际包消费记录为准。可推导声明的操作/位置与关系静态约束及长期验证命令已补齐，后续按实际接入扩展其他浏览器验证及发布准备。每次交付记录修改范围、审查条目、执行命令、实际结果及未验证边界；只有原触发条件和相邻消费者均复查通过，才能关闭对应问题。后续阶段按依赖推进，不能凭计划更新将未实现能力记为完成。

## P0 收尾记录（2026-11-12）

已实现声明字段白名单、缺失/undefined/null 规则、继承层与操作字段错误定位；公共类型接受已明文化的显式 undefined。归一化内部映射使用无原型对象，读取方法覆盖仅使用自有字段，防止 Object.prototype 上的字段进入星号或方法解析。对外结果仍为冻结的普通对象。

新增回归覆盖根及祖先未知字段、不可枚举未知字段、空值、原型字段和未知值字符串转换；原有长继承、循环、冻结及操作优先级回归保留。对应 I04/I06、C04、S01、V01/V03/V05。验证范围为本地声明和包构建，不涉及 HTTP、真实网络、发布或性能结论。
