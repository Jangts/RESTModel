# 文档规范

适用于 RESTModel 仓库、主包体系、扩展包的 README、API 参考、指南、规范、示例、设计提案与维护资料。文档以读者任务和确定的契约组织，不能依靠聊天记录补足含义。

## 正式文档

正式文档描述适用范围内已经确定的产品、设计、接口和操作规则。使用参考以真实公开能力为准；确定但未完成的设计写入明确标识的设计文件，实施差异单独跟踪，不把尚不可执行的示例当上手代码。

- 直接解释用途、前提、输入输出、默认值、覆盖顺序、错误、职责和限制。
- 不叙述开发过程、验收数量、授权、历史写法或沟通背景，不使用“本轮完成”“即将接入”等进度措辞。
- 不设置“待确认”“开放问题”等章节；未决定的选项进入设计提案，不作为产品能力。
- 真实限制应明确。例如未配置操作为空、特殊动作不属于星号、声明对象不是可发送请求的客户端。这些是语义边界，不是进度记录。
- 不把泛型视为运行时校验，不把 HTTP Mock 结果视为真实网络证据，不把内部文件当公共 import。
- 区分库的资源操作与 HTTP method、scheme 与 Transport、主包与扩展、资源声明与运行时资源引用。

## 文档归属与文件位置

| 位置 | 内容及读者 |
| --- | --- |
| 根 README.md | 项目定位、仓库开发入口、公共文档及维护入口 |
| packages/<name>/README.md | 对应包的使用入口 |
| extensions/<name>/README.md | 对应扩展的使用入口及主包兼容要求 |
| docs/README.md | 按用途区分的文档索引 |
| docs/*.md | 正式规范、公共规则与参考；同主题只有一个责任来源 |
| docs/design/ | 提案、设计比较、未决问题，明确标识状态，不等同于可用 API |
| docs/maintenance/ | 实施计划、状态、长期检查及发布记录 |
| development/ 下的专用目录 | 可复用维护脚本；没有脚本时不创建空目录 |

一次性日志、探针和原始输出放系统临时目录或明确忽略的输出目录，不直接散落 docs。长期保留的记录应脱敏、标明对象、版本、证据与结论。移动文档时修正相对链接，保留必要依据，不通过删除未验证记录伪装完成。

正式参考、设计提案、过程资料分别索引。正式正文可以链接维护入口，不复述待办。包 README 不承担发布日志；消费指南不介绍文档站的建设过程。

## API 与配置参考

每个公开入口交代：

1. import 来源和运行前提。
2. 参数及模型泛型含义、返回值、同步或异步行为。
3. 默认值、有效范围、继承与覆盖、缺省与显式空值的区别。
4. 是否复制或冻结、是否持有共享状态、是否产生请求或其他副作用。
5. 错误类型、触发条件、错误阶段及调用方可采取的处理。
6. 最小用法与必要边界；便捷写法和完整写法是否等价。

操作能力示例同时覆盖省略、列表、星号、预设、排除、HTTP 方法覆盖和单体适用性。scheme 文档必须解释其只负责协议适配，不授予资源操作能力；规则按服务复用，不要求逐个配置标准接口。特殊接口必须区分已实现语法和提议语法。

默认值不能靠示例暗示。说明 `0`、空数组、undefined、false、缺失响应及未知 total 的含义，不能统一解释为“无值”。

## 示例要求

- 正式示例使用公开导出，与包实际签名一致；给出类型、依赖、数据和执行位置，不能用无来源的变量冒充完整示例。
- 独立示例应可复现；摘录应标明依赖上下文。网络示例说明所需服务，不使用真实凭据。
- 模拟例子声明 Mock 边界；设计例子置于 design 并标为拟议 API，不进入已发布教程。
- 测试结果和执行环境放维护记录或交付说明；不在 API 正文罗列“通过多少项”。
- 所有 shell 示例使用与项目一致的包管理器；不引导从其他项目借 node_modules。

## 公开包 README 与发布检查

README 要让第一次接触的使用者判断适用场景并完成一次实际使用，包括环境、安装、必需 peer 依赖、完整 import、最小调用和预期结果，再给常用任务与详细参考入口。

发布前核对实际 tarball，而不只核对仓库文件：exports、types、JS、README、许可文件及链接目标都应可交付。相对链接必须随包存在或改成实际公共仓库/站点链接；禁止发布本机绝对路径。尚未发布的包，不以 `npm install` 成功为既有事实；仓库消费与公共安装分别说明。

description/keywords 与实际公开能力相符，不堆未实现功能。发布动作由明确任务授权，不因修改文档自动执行。若执行发布，随后核对公共 registry 中版本、标签、完整性、README 和元数据，记录结果。

不为统一版式重写已完善内容；双语文档保留既定语言顺序和切换锚点。没有双语要求时不主动扩写翻译。

## 同步与审校

接口、配置、默认值或错误变化时同步责任参考、包 README、示例、测试和相关设计来源。生成文档修改来源并重新生成，不只修补产物。维护规范不能覆盖用户已确定的产品规则。

按本次修改选择最小检查：链接、公开签名、示例、生成一致性。文档整理不自动触发全套测试、构建、发布或真实请求。没有执行的验证不得写为通过；判断按语义进行，不批量删除“历史”“后续”等可能合法的产品词汇。
