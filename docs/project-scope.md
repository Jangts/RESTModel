# 项目边界

## 定位

服务 RESTful API 及其变体，保留模型化与链式操作。标准接口近乎免配；服务级 scheme 一次适配共性规则，资源与操作继承，配置主要处理例外。少量特殊接口必须显式配置，并尽量简化声明。不以通用 RPC 或任意数据源访问作为目标。

主包默认使用内置 Fetch 发送真实 HTTP 请求；普通调用不要求配置执行器。Transport 是可替换 HTTP 执行器的扩展契约，不能绕开 RESTful 推导与服务规则，不作为入门前置概念。主包不依赖 Axios，不暴露 Axios 类型。主包定义资源模型、链式上下文、HTTP 请求与结果契约、默认推导、scheme 规则和扩展接入点。不要为每个标准接口重复声明 URL、方法和参数转换。

## 标准操作例外与动作

标准 RESTful 接口按默认方法与路径推导。标准操作只有单身份地址例外时，覆盖 path 与 queryKey 或单个 `:id`，保留 `api.users(id).get()` 等调用及正常实体结果。接口例外需要多个业务入参或额外行为时使用 action。动作声明名与后端路径独立，按声明名直接调用；多个具名路径参数从输入对象提取，剩余字段进入 query/body。此规则不限制普通 list 筛选条件或模型请求体字段。具体规则见[操作声明](operations.md)和[动作路径参数](client.md#动作路径参数)。

## 扩展

请求实现、Mock、缓存、Pinia 等集成都属于扩展能力，不进入主包。具体扩展实现与交付范围由各包的公开入口和维护资料说明。

扩展分为随主包迭代的正式配套与独立维护的第三方。扩展可采用伪三方方式：即使同一作者、同一仓库维护，也只使用公开契约，独立声明兼容范围、独立发布，不承诺同步升级。不设统一版本或固定版本组。各包不因同一仓库而共享固定版本。

扩展对核心使用 workspace peer dependency；具体兼容范围应在发布时明确，开发版本不能视作已发布的兼容承诺。

## Mock

Mock 是本项目提供的 HTTP 调试扩展，必须服从 HTTP。复用资源推导和 scheme 适配后的最终请求，按方法、URL、参数、请求体匹配并返回状态码、响应头、响应体，可模拟延迟与网络错误。不得绕过 HTTP 流程直接按资源操作返回业务结果。

## 缓存和状态管理

缓存作为可选扩展，由本库定义数据结构、键、有效期和失效规则。允许替换存储介质，不负责适配任意业务 Store。Pinia 等封装在主包基础上集成状态管理，不改变主包的数据访问边界。

## 维护原则

使用者易用、易学优先。内部复杂度可以存在，但对外概念与行为必须清晰、稳定。保留模型化和链式特征，优先简化概念，不以减少内部实现代码为目的牺牲调用体验。通用能力优先评估成熟依赖，避免继续绑定原工具集临包。
