快速上手 ​

RESTModel 将 RESTful 接口组织成集合、成员和单体资源，使用显式能力声明约束调用。核心不依赖 UI 框架，也不依赖 Axios。

环境与工作区消费 ​

使用 Node.js 22+、pnpm 8.10.5。浏览器需支持 Fetch、AbortController 和 FormData。主包与三个扩展均面向公共发布，尚未公开发布；以下命令在本仓库根目录执行，不依赖公共 registry 中存在 RESTModel 包。

sh
pnpm install
pnpm build

工作区包使用 workspace:* 引用 @restmodel/restmodel。仓库外可在 packages/restmodel 执行 pnpm pack --pack-destination /tmp/restmodel-pack，再在消费项目中用 pnpm add /tmp/restmodel-pack/实际生成的文件名.tgz 安装；扩展包同时需要主包 tarball 和各自 peer 依赖。打包使用 pnpm，以便将 workspace 依赖转换为公开版本范围；prepack 会清理并重新构建当前包的 dist。

第一次资源调用 ​

将下面代码放入消费项目的 TypeScript 模块中运行。示例使用内存 Transport，无需后端，也不会发出网络请求。

ts
import { createClient, resource, dataOf } from '@restmodel/restmodel';

interface User { id: number; name: string }

const api = createClient({
  baseURL: 'https://example.test/api',
  transport: async request => {
    if (request.method === 'GET' && request.url === 'https://example.test/api/users') {
      return { status: 200, headers: {}, body: [{ id: 0, name: 'Ivan' }] };
    }
    return { status: 404, headers: {}, body: { message: 'Not found' } };
  },
  resources: {
    users: resource<User>({ operations: ['list', 'get'] }),
  },
});

const users = await api.users.list();
console.log(users.items.map(user => dataOf(user)));
// [{ id: 0, name: 'Ivan' }]
console.log(users.total); // undefined：服务没有提供总数

模型泛型用于 TypeScript 提示，不执行响应数据校验。这段示例验证资源调用及结果适配；真实 HTTP 行为需连接实际服务验证。

连接 REST 服务 ​

将上例的 transport 替换为 fetchTransport()，从 @restmodel/restmodel 导入。将 baseURL 改成实际服务地址；默认列表响应应为裸数组，记录身份字段为 id。Node 使用绝对 HTTP(S) 地址，浏览器可用 /api，跨源服务需配置 CORS。

ts
import { fetchTransport } from '@restmodel/restmodel';
// createClient 配置中使用 transport: fetchTransport()

api.users.list() 对应 GET /api/users，api.users(0).get() 对应 GET /api/users/0。只有显式声明的操作可用；需要新增或修改记录时，在 operations 中声明 post、patch 等相应能力。

接下来 ​

  • 资源操作声明：白名单、星号、预设和覆盖。
  • 客户端参考：查询、分页、信封、关系、特殊动作与错误处理。
  • 扩展选型：接入 Axios、HTTP Mock 或 Pinia。

资源引用的 query/page/cursor/with 返回新引用，本地实体字段修改不会自动发送请求。RESTModel 不自动重试写操作，也不内置缓存。
